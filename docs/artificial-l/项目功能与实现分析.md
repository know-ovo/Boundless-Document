# 无界文档 (Boundless Document) — 项目功能与实现分析

## 一、项目概述

**无界文档 (Boundless Document)** 是一个基于 Tauri + React 的桌面端 Markdown 编辑器，核心理念是"可执行文档"——在传统 Markdown 文档中嵌入**增强块 (Enhanced Blocks)**，使文档具备实时数据绑定、多语言代码执行、数据可视化和多媒体展示能力。

- **项目名称**: `boundless-docs` v0.1.0
- **仓库类型**: npm workspaces monorepo
- **技术栈**: TypeScript + React 19 + Tauri 2 + BlockNote (TipTap/ProseMirsky)
- **许可证**: Apache-2.0

## 四、核心功能及其实现

### 功能 1：WYSIWYG Markdown 编辑器

**文件**: [packages/editor/src/BlockNoteEditor.tsx](packages/editor/src/BlockNoteEditor.tsx)

基于 BlockNote (v0.49.0，底层为 TipTap/ProseMirsky) 构建。启动时通过 `editor.tryParseMarkdownToBlocks()` 将 Markdown 解析为 BlockNote 的块结构（`initialMarkdown` → blocks）。编辑器内任何修改触发 `editor.blocksToMarkdownLossy()` 反向导出 Markdown，通过 `onMarkdownChange` 回调通知父组件。

BlockNote Schema 在 [schema.ts](packages/editor/src/schema.ts) 中定义，使用 `defaultBlockSpecs`（支持段落、标题、列表、代码块、图片等标准 Markdown 元素）。Schema 预留了自定义 block spec 的插入点。

**关键技术细节**:
- 使用 `editorMountKey`（= `${docSession}:${fileName}:${content.length}`）确保切换文档时 Editor 实例完全重建
- 使用 `hydratedRef` 确保 `initialMarkdown` 仅在挂载时注入一次

### 功能 2：增强块系统（Enhanced Blocks）

增强块是项目的核心创新——在 Markdown 文档内使用 fenced code block 标记（如 ` ```live-data`、` ```run-python` 等）嵌入交互式内容。

#### 2.1 支持的 7 种增强块

| 种类 | 代码块标记 | 功能 | 实现组件 |
|------|-----------|------|---------|
| 实时数据 | ` ```live-data` | 绑定外部数据源（polling/SSE/WebSocket） | [LiveDataBlockView.tsx](packages/blocks/src/components/LiveDataBlockView.tsx) |
| JavaScript | ` ```run-js` | 在 Web Worker 沙箱中执行 JS 代码 | [CodeBlockView.tsx](packages/blocks/src/components/CodeBlockView.tsx) |
| Python | ` ```run-python` | 通过 Pyodide 在浏览器中执行 Python | [PythonBlockView.tsx](packages/blocks/src/components/PythonBlockView.tsx) |
| SQL | ` ```sql` | 通过 DuckDB-Wasm 在浏览器中执行 SQL | [SQLBlockView.tsx](packages/blocks/src/components/SQLBlockView.tsx) |
| 图表 | ` ```chart` | 使用 ECharts 渲染独立图表 | [ChartBlockView.tsx](packages/blocks/src/components/ChartBlockView.tsx) |
| 3D 模型 | ` ```model3d` | 渲染 glTF/GLB 3D 模型 | [Model3dBlockView.tsx](packages/blocks/src/components/Model3dBlockView.tsx) |
| 多媒体 | ` ```asset` | 嵌入图片/视频/音频/PDF | [AssetBlockView.tsx](packages/blocks/src/components/AssetBlockView.tsx) |

#### 2.2 增强块的解析流程

**第一阶段 — Markdown 解析** ([packages/shared/src/markdownBlocks.ts](packages/shared/src/markdownBlocks.ts))

```
Markdown 文本
  │
  ├─→ extractFrontmatter()    → 正则 /^---\n([\s\S]*?)\n---\n?/
  │     └─→ parseYamlObject()  → 用 yaml 库解析，返回 DocumentFrontmatter
  │
  └─→ parseBoundlessBlocks()  → 正则 /^```([\w-]+)\s*\n([\s\S]*?)\n```/gm
        │
        └─→ 过滤 enhancedKinds（7 种）→ createBlock(kind, raw, order)
              │
              ├─ live-data → YAML 解析 → LiveDataBlock { source, mode, interval, view }
              ├─ run-js    → 原始文本 → RunJsBlock { code, timeoutMs: 3000 }
              ├─ run-python→ 原始文本 → RunPythonBlock { code, timeoutMs: 5000 }
              ├─ sql       → 原始文本 → SqlBlock { code, timeoutMs: 10000 }
              ├─ chart     → YAML 解析 → ChartBlock { config: {...} }
              ├─ model3d   → YAML 解析 → Model3dBlock { src, autoRotate, cameraControls, height }
              └─ asset     → YAML 解析 + 扩展名推断 → AssetBlock { src, type, title }
```

**第二阶段 — UI 渲染** ([packages/blocks/src/BlockPreviewPanel.tsx](packages/blocks/src/BlockPreviewPanel.tsx))

```
BoundlessBlock[]
  │
  ├─→ BlockPreviewPanel（侧边栏预览）
  │     └─→ BlockCard → 根据 block.kind 分发到对应 *BlockView
  │
  └─→ InlineDocumentView（内嵌文档视图）
        └─→ splitMarkdownIntoInlineParts()
              │
              ├─ 普通 Markdown → react-markdown 渲染
              └─ 增强块 fenced block → BoundlessBlockView 分发
```

#### 2.3 增强块的插入方式

**斜杠菜单** ([packages/editor/src/slash-menu.ts](packages/editor/src/slash-menu.ts))

编辑器内输入 `/` 触发 BlockNote 的 `SuggestionMenuController`，7 个自定义菜单项属于 "Enhanced Blocks" 分组。选中后调用 `insertSnippet()`：
1. 关闭斜杠触发块（插入 paragraph）
2. 调用 `editor.tryParseMarkdownToBlocks(snippet)` 将 Markdown 片段解析为 BlockNote blocks
3. 通过 `editor.insertBlocks()` 在光标处插入

**片段模板** ([packages/editor/src/snippets.ts](packages/editor/src/snippets.ts))

每个增强块都有预置的 Markdown 模板，包含示例 YAML 配置：
- `live-data`: GitHub API 轮询示例
- `run-js`: 随机数据生成示例
- `run-python`: statistics 均值/中位数
- `sql`: `SELECT 1 UNION ALL SELECT 2 UNION ALL SELECT 3`
- `model3d`: Astronaut.glb 模型
- `asset`: Unsplash 图片

### 功能 3：运行时沙箱系统

**核心文件**: [packages/runtime/src/sandbox/sandboxRunner.ts](packages/runtime/src/sandbox/sandboxRunner.ts)

三个代码执行后端（JS / Python / SQL）共享统一的 Worker 池架构。

#### 3.1 Worker 池架构

```
executeInSandbox(key, factory, code, timeoutMs)
  │
  ├─→ key='js'     → jsSandbox.worker.ts   → new Function()
  ├─→ key='python' → python.worker.ts      → Pyodide (WASM)
  └─→ key='sql'    → sql.worker.ts         → DuckDB-Wasm (WASM)
```

**设计特点**:
- **每键单 Worker**: 每种语言一个 Worker，全局复用
- **任务队列**: 同键并发请求排队，不中止
- **Warm Worker**: 首次执行触发 WASM 下载（Pyodide/DuckDB），后续调用复用
- **超时机制**: 可配置超时，超时后 `terminate()` 并创建新 Worker
- **取消支持**: 调用 `cancel()` 可中止执行/从队列移除
- **进度消息**: Worker 可发送 `{ type: 'progress', message }` 用于加载状态通知

```typescript
// 执行接口
interface SandboxExecution {
  promise: Promise<SandboxResult>;
  cancel: () => void;
}

// 结果接口
interface SandboxResult {
  ok: boolean;
  value?: unknown;
  error?: string;
  logs: string[];
  durationMs: number;
}
```

#### 3.2 JS 沙箱 ([jsSandbox.worker.ts](packages/runtime/src/jsSandbox.worker.ts))

使用 `new Function("console", \`"use strict"; return (async () => { ${code} })()\`)` 在 Worker 中执行。提供 `safeConsole` 对象捕获 `log/info/warn/error` 输出。

**自定义序列化器 `serializeValue()`**: 处理 JSON.stringify 无法正确表示的 JavaScript 值：
- `BigInt` → `{ __bigint: "123" }`
- `Symbol` → `{ __symbol: "name" }`
- `undefined` → `{ __undefined: true }`
- `NaN` → `{ __nan: true }`
- `Infinity/-Infinity` → `{ __inf: "Infinity" }`
- 函数 → `{ __function: "name" }`
- Error → `{ __error: true, name, message, stack }`
- 循环引用 → `{ __circular: "<ref path>" }`（用 WeakMap 追踪）

#### 3.3 Python 沙箱 ([python.worker.ts](packages/runtime/src/sandbox/python.worker.ts))

- 动态导入 `pyodide` 并调用 `loadPyodide({ indexURL: 'https://cdn.jsdelivr.net/pyodide/v0.29.3/full/' })`
- `ensurePyodide()` 确保只初始化一次（`pyodideReady` 标志）
- 自动从代码中的 imports 加载包（`loadPackagesFromImports`）
- 捕获 stdout/stderr 输出（`setStdout/setStderr`）
- 返回输出行和 `runPython()` 的返回值

**初始化方式**: `loadPyodideOnce()` 通过执行 `'42'` 触发首次 WASM 下载，实际用户代码后续使用已初始化的 Pyodide 实例。

#### 3.4 SQL 沙箱 ([sql.worker.ts](packages/runtime/src/sandbox/sql.worker.ts))

- 导入 `@duckdb/duckdb-wasm`，使用 `getJsDelivrBundles()` 从 CDN 加载
- `ensureDuckDB()` 确保只初始化一次（`dbReady` 标志）
- 配置 `castBigIntToDouble: true` 避免 BigInt 序列化问题
- 每次查询：`connect()` → `query()` → 提取 columns + rows → `close()`
- 结果返回 `{ columns: string[], rows: string[][] }`

### 功能 4：实时数据订阅

**文件**: [packages/runtime/src/dataSource.ts](packages/runtime/src/dataSource.ts)

`subscribeToLiveData(block, onSnapshot)` 支持三种数据获取模式：

| 模式 | 实现方式 | 适用场景 |
|------|---------|---------|
| `polling` | `setInterval(fetchOnce, interval)` + `fetch()` | REST API 定时轮询 |
| `sse` | `new EventSource(source)` | 服务端推送事件 |
| `websocket` | `new WebSocket(source)` | 双向实时通信 |

**返回的 DataSubscription 接口**:
```typescript
interface DataSubscription {
  pause: () => void;   // 暂停数据流（停止定时器/关闭连接）
  resume: () => void;  // 恢复数据流（重新开始）
  dispose: () => void; // 永久销毁（组件卸载时调用）
}
```

**数据状态机**: `idle → connecting → open` (成功) / `idle → connecting → error` (失败)，`open → paused` (暂停)。最小轮询间隔为 1000ms。

**数据标准化** (`normalizeRows()`): 将原始数据转换为行数组用于表格/图表：
- 如果值是数组 → 过滤出对象元素
- 如果值是对象 → 查找嵌套数组字段，否则包装为单元素数组

### 功能 5：数据可视化

#### 5.1 ECharts 独立图表 ([ChartBlockView.tsx](packages/blocks/src/components/ChartBlockView.tsx))

按需导入 ECharts 模块（BarChart, LineChart, GridComponent, TooltipComponent, CanvasRenderer）。支持通过 YAML 配置 `type: 'bar' | 'line'` 和 `data: [number, ...]`。

**实现细节**:
- `echarts.init(containerRef.current)` 初始化实例
- `window.resize → chart.resize()` 自适应
- 组件卸载时 `chart.dispose()` 清理
- X 轴为自动生成的序号 `["1", "2", "3", ...]`

#### 5.2 实时数据图表 ([charts.tsx](packages/blocks/src/components/charts.tsx))

为 `LiveDataBlockView` 提供折线图/柱状图渲染。使用 `block.config.x` 和 `block.config.y` 作为数据轴键。通过 `normalizeRows()` 将数据转换为 `{x轴, y轴}` 形式的 ECharts 数据集。

### 功能 6：3D 模型渲染

**文件**: [Model3dBlockView.tsx](packages/blocks/src/components/Model3dBlockView.tsx)

使用 Google 的 `<model-viewer>` Web Component 渲染 glTF/GLB 格式的 3D 模型。配置项通过 YAML frontmatter 传入：
- `src`: 模型 URL
- `poster`: 加载前显示的占位图
- `autoRotate`: 自动旋转（默认 true）
- `cameraControls`: 用户可交互控制摄像机（默认 true）
- `height`: 视口高度（默认 360px）

背景色使用深色 (`#0f172a`) 以适配大多数 3D 模型展示。

### 功能 7：多媒体资源嵌入

**文件**: [AssetBlockView.tsx](packages/blocks/src/components/AssetBlockView.tsx)

根据 `type` 属性渲染不同类型的媒体：

| type | 渲染方式 | 特殊处理 |
|------|---------|---------|
| `image` | `<img loading="lazy">` | — |
| `video` | `<video controls preload="metadata">` | — |
| `audio` | `<audio controls>` | — |
| `pdf` | `<iframe>` | — |
| `unknown` | `<a target="_blank">` | 作为链接打开 |

**类型推断** ([markdownBlocks.ts:230-249](packages/shared/src/markdownBlocks.ts#L230-L249)): 如果未显式指定 `type`，通过文件扩展名自动推断：
- `png/jpg/jpeg/gif/webp/svg` → image
- `mp4/webm/mov` → video
- `mp3/wav/ogg` → audio
- `pdf` → pdf

### 功能 8：文件管理

**文件**: [apps/desktop/src/fileService.ts](apps/desktop/src/fileService.ts)

抽象了 Tauri 原生和浏览器两种模式，通过 `'__TAURI_INTERNALS__' in window` 检测运行环境。

#### Tauri 桌面模式
```
openMarkdownFile()
  └─→ open({ filters: [{ name: 'Markdown', extensions: ['md', 'markdown'] }] })
        └─→ readTextFile(path)  → 返回 OpenedDocument

saveMarkdownFile(content, currentPath?)
  ├─ 有 currentPath → 直接 writeTextFile()
  └─ 无 currentPath → save({ filters: [{ extensions: ['md'] }] })
        └─→ 用户选择路径 → writeTextFile(path, content)

readMarkdownFromPath(path)
  └─→ readTextFile(path)
```

#### 浏览器回退模式
```
openMarkdownFile()
  └─→ <input type="file" accept=".md,.markdown">
        └─→ file.text()  → 返回 OpenedDocument

saveMarkdownFile()
  └─→ Blob + <a download> → 触发浏览器下载
```

#### Tauri 权限配置

在 [capabilities/default.json](apps/desktop/src-tauri/capabilities/default.json) 中限制文件系统访问范围：
- `fs:allow-read-text-file` / `fs:allow-write-text-file` 限制在 `$DOCUMENT/**`, `$DOWNLOAD/**`, `$DESKTOP/**`, `$HOME/*.md`

### 功能 9：文档管理（App.tsx 核心状态机）

**文件**: [apps/desktop/src/App.tsx](apps/desktop/src/App.tsx)

#### 文档状态模型

```
docContent (原始 Markdown 文件内容)
  │
  ├─→ parseBoundlessDocument() → parsedDoc { frontmatter, markdown, blocks }
  │
  └─→ liveMarkdown (编辑器当前内容，随编辑实时更新)
        │
        └─→ 与 lastSavedMarkdown 比较 → dirty 标志
```

#### 待处理操作 (PendingOp) 状态机

在切换/新建/打开文档前，如果有未保存修改，系统进入 pending 状态：

```typescript
type PendingOp =
  | { type: 'new' }                          // 新建文档
  | { type: 'open-picker' }                  // 文件选择器
  | { type: 'landing' }                      // 回到落地页
  | { type: 'apply-doc'; doc: OpenedDocument } // 拖放文件
  | { type: 'load-path'; path: string }      // 从最近文件打开
```

**交互流程**:
```
用户操作（新建/打开/切换）
  │
  ├─ dirty === false → 直接执行 executePending()
  │
  └─ dirty === true → setPendingOp()
        └─→ UnsavedChangesModal 弹出
              ├─ "保存并继续" → saveDocument() → executePending()
              ├─ "放弃更改"   → executePending()
              └─ "取消"       → setPendingOp(null)
```

#### Ctrl+S 保存快捷键

全局 `keydown` 监听，跳过等待中的操作/不脏时/保存中时。调用 `saveDocument()`。

#### 最近文件 (Recent Files)

保存在内存中的数组（最多 8 个），通过 `applyDocument()` 在每次打开文件时更新。通过侧边栏 `sidebarRows` 展示，支持按文件名/路径过滤搜索。

#### 拖放打开

侧边栏区域支持 HTML5 Drag & Drop，接受 `.md` / `.markdown` 文件。通过 `handleDroppedMarkdownFile()` 处理。

## 六、安全设计

1. **CSP 限制**：Tauri 窗口 CSP 限制脚本来源为 `'self'`，显式允许 `'unsafe-eval'` 和 `'wasm-unsafe-eval'` 以适应 Pyodide/DuckDB 的 WASM 运行时
2. **文件系统权限**: Tauri 权限限定在文档/下载/桌面目录及家目录 `.md` 文件
3. **Worker 隔离**: JS/Python/SQL 代码均在 Web Worker 中执行，无法直接访问 DOM
4. **JS 沙箱**: 使用 `new Function()` + strict mode 执行，不提供 `window`/`document` 访问
5. **协作默认关闭**: Yjs WebRTC 协作默认禁用，需显式启用
6. **超时保护**: 所有代码执行都有超时限制（JS: 3s, Python: 5s, SQL: 10s）
