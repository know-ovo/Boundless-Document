## 1. 产品概述

### 1.1 产品定位

**无界文档 (Boundless Document)** 是一款"超级文档"创作工具——它在传统 Markdown 的基础上，通过**增强块 (Enhanced Blocks)** 机制，将实时数据、可执行代码、3D 模型、多媒体资产和交互式图表直接嵌入文档正文，让文档从静态的"文字页面"升级为动态的"可交互知识容器"。

### 1.2 解决的问题

传统文档工具的局限：

| 痛点 | 无界文档的解法 |
|------|---------------|
| 文档与数据脱节——截图粘贴、手动更新 | `live-data` 块直连数据源，实时渲染 |
| 代码示例只能"看"不能"跑" | `run-js` / `run-python` / `sql` 块在沙箱中实际执行 |
| 3D 模型、多媒体只能外链 | `model3d` / `asset` 块原生嵌入渲染 |
| 文档格式绑定特定编辑器 | 基于标准 Markdown + YAML frontmatter，纯文本可迁移 |
| 写作与编程的割裂 | 在同一个文档中写作、编码、可视化，无需切换工具 |

### 1.3 目标用户

- **技术写作者**：撰写可执行的 API 文档、技术教程
- **数据分析师**：构建带实时数据仪表盘的报告
- **产品设计师**：制作嵌入 3D 模型的交互式产品说明书
- **研究人员**：记录包含可复现实验代码的研究笔记
- **开发者**：编写可运行的技术方案、架构决策记录

### 1.4 设计原则

1. **Markdown 优先**：文档本体是标准 Markdown，增强块以 fenced code block 形式嵌入，纯文本即可迁移
2. **渐进增强**：不支持增强块的阅读器仍能查看原始内容，不会丢失信息
3. **安全隔离**：所有代码在 Web Worker 沙箱中执行，不影响主界面
4. **可组合架构**：核心能力按包拆分，桌面端、Web 端、编辑器插件共享同一套包

## 2. 核心概念

### 2.1 文档模型

一份无界文档由三层信息组成：

```
┌──────────────────────────────────────────┐
│           Document Frontmatter           │  ← YAML 元数据
│  title, permissions, createdAt, ...      │
├──────────────────────────────────────────┤
│           Markdown Body                  │  ← 标准 Markdown 正文
│  # 标题                                  │
│  段落文字...                              │
│  ```live-data ... ```                    │  ← 增强块（嵌入在正文中）
│  ```run-js ... ```                      │
├──────────────────────────────────────────┤
│           Parsed Blocks                  │  ← 解析后的增强块列表
│  [LiveDataBlock, RunJsBlock, ...]        │
└──────────────────────────────────────────┘
```

### 2.2 增强块 (Enhanced Blocks)

增强块是本产品的核心创新。通过在 Markdown 中使用 fenced code block 并指定特殊的语言标识符，编写者可以在文档中嵌入七种可交互组件：

| 块类型 | 语言标识 | 功能 |
|--------|---------|------|
| `live-data` | `live-data` | 连接实时数据源，支持轮询/SSE/WebSocket，自动渲染为 JSON/表格/图表 |
| `run-js` | `run-js` | 在 Web Worker 沙箱中执行 JavaScript，返回结果就地展示 |
| `run-python` | `run-python` | 通过 Pyodide (WASM) 在浏览器中运行 Python |
| `sql` | `sql` | 通过 DuckDB-WASM 在浏览器中执行 SQL 查询 |
| `chart` | `chart` | 基于 ECharts 的交互式图表 |
| `model3d` | `model3d` | 嵌入 glTF/GLB 3D 模型，支持旋转、缩放、海报图 |
| `asset` | `asset` | 嵌入图片、视频、音频、PDF 等多媒体资产 |

### 2.3 Frontmatter 权限控制

文档头部 YAML 支持权限声明，控制增强块的运行时行为：

```yaml
---
title: 文档标题
permissions:
  allowNetwork: true        # 允许 live-data 块发起网络请求
  allowedOrigins:           # 白名单来源（预留）
    - https://api.example.com
---
```

## 3. 功能体系

### 3.1 当前已实现 (v0.1.0)

#### 3.1.1 编辑器

- 基于 BlockNote 的富文本 Markdown 编辑
- 源码模式切换
- 增强块代码语法高亮

#### 3.1.2 实时数据 (`live-data`)

- 三种数据获取模式：**轮询 (Polling)**、**SSE (Server-Sent Events)**、**WebSocket**
- 四种展示视图：**JSON 原样输出**、**表格**、**折线图**、**柱状图**
- 支持暂停/恢复数据订阅
- 可配置轮询间隔（最小 1 秒）

#### 3.1.3 代码执行 (`run-js`, `run-python`, `sql`)

- `run-js`：Web Worker 沙箱执行 JavaScript，默认超时 3s
- `run-python`：通过 Pyodide (CPython WASM 编译版) 执行 Python，默认超时 30s，首次自动下载约 12MB
- `sql`：通过 DuckDB-WASM 在浏览器内执行 SQL，默认超时 10s
- 统一沙箱调度器：每语言一个 warm worker，支持并发排队、取消执行
- 执行结果展示：成功/失败状态、耗时、console 输出、返回值/错误信息

#### 3.1.4 3D 模型 (`model3d`)

- 基于 `@google/model-viewer` 渲染 glTF/GLB 模型
- 支持自动旋转、相机控制、自定义海报图
- 可调高度

#### 3.1.5 多媒体资源 (`asset`)

- 支持类型：图片 (png/jpg/webp/svg)、视频 (mp4/webm)、音频 (mp3/wav)、PDF 内嵌
- 自动根据文件扩展名推断类型
- 未识别类型显示为外链

#### 3.1.6 图表 (`chart`)

- 基于 ECharts (按需引入 Line/Bar + Grid/Tooltip)
- 当前与 `live-data` 的数据展示共用，`live-data` 的 `view` 设为 `line`/`bar` 时使用

#### 3.1.7 桌面应用

- Tauri 2 桌面壳：窗口管理、本地文件系统访问、系统对话框
- 打开/保存本地 `.md` 文件
- 默认内置 Demo 文档

#### 3.1.8 UI 个性化

- 浅色/深色主题切换
- 自定义强调色（预设多种颜色）
- 字体风格切换（无衬线/衬线）
- 页面宽度切换（标准居中/宽屏）

### 3.2 设计中/规划中的功能

- **实时协作**：基于 Yjs + CRDT 的多人在线协同编辑
- **AI 集成**：文档索引、语义搜索、AI 问答（带引用）、自动摘要
- **Web 版**：复用现有包构建纯 Web 版本
- **编辑器插件**：VS Code / Cursor / Obsidian 插件
- **Python/SQL 代码块结果可视化增强**
- **Markdown 内联增强块**（正文中就地渲染）

## 5. 包与模块设计

项目采用 pnpm workspace monorepo 结构：

### 5.1 `packages/shared` — 共享类型与解析

**职责**：文档类型定义、frontmatter 解析、增强块解析（依赖层级：叶子包，无内部依赖）

核心导出：

| 导出 | 说明 |
|------|------|
| `BoundlessBlock` 联合类型 | 七种增强块的 TypeScript 类型 |
| `DocumentFrontmatter` | 文档元数据类型 |
| `ParsedDocument` | 完整解析结果 |
| `parseBoundlessDocument()` | 解析 Markdown 全文 |
| `parseBoundlessBlocks()` | 仅解析增强块 |
| `extractFrontmatter()` | 提取 YAML 头 |
| `createBlock()` | 工厂函数，按 kind 创建块对象 |
| `AiAdapter` / `CollaborationAdapter` | 扩展点接口（预留） |

### 5.2 `packages/editor` — 编辑器封装

**职责**：Markdown 编辑器封装，基于 BlockNote (ProseMirror)

- 提供统一的 `editorSchema`，支持自定义 BlockSpec 注册
- 当前为 BlockNote 默认块规格，后续可扩展自定义增强块节点

### 5.3 `packages/blocks` — 增强块渲染

**职责**：所有增强块的 UI 渲染组件

**依赖**：`packages/shared`、`packages/runtime`

核心组件：

| 组件 | 对应块类型 | 说明 |
|------|-----------|------|
| `BlockPreviewPanel` | 全部 | 侧边栏增强块列表总览 |
| `InlineDocumentView` | 全部 | 正文内联渲染（Markdown + 增强块混合） |
| `LiveDataBlockView` | `live-data` | 实时数据展示、JSON/表格/图表视图 |
| `CodeBlockView` | `run-js` | JS 代码执行与结果展示 |
| `PythonBlockView` | `run-python` | Python 代码执行与结果展示 |
| `SQLBlockView` | `sql` | SQL 查询执行与结果展示 |
| `ChartView` | 图表渲染 | ECharts 折线图/柱状图（被 LiveDataBlockView 使用） |
| `Model3dBlockView` | `model3d` | 3D 模型渲染（model-viewer） |
| `AssetBlockView` | `asset` | 图片/视频/音频/PDF 渲染 |

### 5.4 `packages/runtime` — 运行时能力

**职责**：代码执行沙箱、数据源订阅、Pyodide/DuckDB 运行时管理

**依赖**：`packages/shared`

核心模块：

| 模块 | 功能 |
|------|------|
| `sandbox/sandboxRunner.ts` | 统一 Worker 池调度器——每语言一个 warm worker，支持排队、取消、超时 |
| `codeRunner.ts` | JavaScript 沙箱执行入口 |
| `pyodideRunner.ts` | Pyodide 生命周期管理与 Python 执行 |
| `duckDBRunner.ts` | DuckDB-WASM 生命周期管理与 SQL 执行 |
| `dataSource.ts` | 实时数据订阅——polling/SSE/WebSocket 三种模式 |
| `RuntimeContext.tsx` | React Context 提供 Pyodide/DuckDB 状态 |

沙箱 Worker 文件：

| Worker | 职责 |
|--------|------|
| `jsSandbox.worker.ts` | JavaScript 执行环境 |
| `sandbox/python.worker.ts` | Python (Pyodide) 执行环境 |
| `sandbox/sql.worker.ts` | SQL (DuckDB-WASM) 执行环境 |

### 5.5 `apps/desktop` — Tauri 桌面应用

**职责**：Tauri 宿主、React 应用入口、默认文档、UI 设置

**技术**：Tauri 2 (Rust) + React 18 + Vite + Mantine UI

核心文件：

| 文件 | 说明 |
|------|------|
| `src/main.tsx` | React 入口，挂载 App + SettingsProvider |
| `src/defaultDocument.ts` | 内置 Demo 文档 |
| `src-tauri/src/lib.rs` | Tauri 后端——注册 dialog 和 fs 插件 |
| `src-tauri/Cargo.toml` | Rust 依赖声明 |
| `vite.config.ts` | Vite 配置——端口 1420，ES module worker |

## 6. 数据模型

### 6.1 块类型定义

```typescript
type BoundlessBlockKind =
  | 'live-data'
  | 'run-js'
  | 'run-python'
  | 'sql'
  | 'chart'
  | 'model3d'
  | 'asset';

interface BaseBoundlessBlock {
  id: string;       // 自动生成："{kind}-{order+1}"
  kind: BoundlessBlockKind;
  raw: string;      // fenced code block 原始内容
  order: number;    // 在文档中的顺序
}
```

### 6.2 各块专属字段

#### LiveDataBlock

```typescript
{
  kind: 'live-data';
  config: {
    source: string;       // 数据源 URL
    mode: 'polling' | 'sse' | 'websocket';
    interval: number;     // 轮询间隔 (ms)，默认 5000
    view: 'json' | 'table' | 'line' | 'bar';  // 展示视图
    x?: string;           // 图表 X 轴字段
    y?: string;           // 图表 Y 轴字段
  };
}
```

#### RunJsBlock / RunPythonBlock / SqlBlock

```typescript
{
  kind: 'run-js' | 'run-python' | 'sql';
  code: string;           // 源代码
  timeoutMs: number;      // 超时 (JS: 3000, Python: 30000, SQL: 10000)
}
```

#### Model3dBlock

```typescript
{
  kind: 'model3d';
  config: {
    src: string;              // glTF/GLB 模型 URL
    poster?: string;          // 海报图 URL
    autoRotate: boolean;      // 自动旋转，默认 true
    cameraControls: boolean;  // 相机控制，默认 true
    height: number;           // 高度 px，默认 360
  };
}
```

#### AssetBlock

```typescript
{
  kind: 'asset';
  config: {
    src: string;             // 资源 URL
    type: 'image' | 'video' | 'audio' | 'pdf' | 'unknown';
    title?: string;          // 资源标题
  };
}
```

### 6.3 运行时类型

```typescript
// 沙箱执行结果
interface SandboxResult {
  ok: boolean;
  value?: unknown;
  error?: string;
  logs: string[];
  durationMs: number;
}

// 数据订阅快照
interface DataSnapshot {
  status: 'idle' | 'connecting' | 'open' | 'error' | 'paused';
  value: unknown;
  error?: string;
  updatedAt?: string;
}
```

### 6.4 扩展点接口（预留）

#### 协作适配器

```typescript
interface CollaborationAdapter {
  connect(documentId: string): Promise<void>;
  disconnect(): Promise<void>;
  applyLocalUpdate(update: Uint8Array): void;
  onRemoteUpdate(handler: (update: Uint8Array) => void): () => void;
}
```

#### AI 适配器

```typescript
interface AiAdapter {
  indexDocument(source: AiDocumentSource): Promise<void>;
  answer(question: string, documentId?: string): Promise<AiAnswer>;
  summarize(documentId: string): Promise<string>;
}
```

### 7.2 视觉设计

## 8. 运行时与沙箱

### 8.1 沙箱架构

所有代码执行在 Web Worker 中进行，与主线程完全隔离：

```
┌──────────────────────────────────────┐
│            Main Thread               │
│  ┌────────────────────────────────┐  │
│  │     SandboxRunner (Pool)       │  │
│  │  ┌──────┐ ┌──────┐ ┌──────┐   │  │
│  │  │  JS  │ │Python│ │ SQL  │   │  │
│  │  │Worker│ │Worker│ │Worker│   │  │
│  │  └──────┘ └──────┘ └──────┘   │  │
│  └────────────────────────────────┘  │
│                                      │
│  ┌────────────────────────────────┐  │
│  │        DataSource              │  │
│  │  fetch() / EventSource / WS    │  │
│  └────────────────────────────────┘  │
└──────────────────────────────────────┘
```

### 8.2 Worker 池调度策略

- 每种语言 (`js` / `python` / `sql`) 维护一个 **warm worker**
- 同一语言的并发请求**排队执行**（不创建新 Worker）
- 首次执行触发 WASM 运行时下载（Pyodide ~12MB / DuckDB-WASM）
- 后续调用即时响应，Worker 保持温热
- 超时：终止当前 Worker，自动重建
- 取消：支持通过 `cancel()` 终止执行

### 8.3 安全策略

1. **代码隔离**：所有用户代码在 Web Worker 中执行，无法访问 DOM
2. **网络控制**：通过 frontmatter `permissions.allowNetwork` 声明式控制网络权限
3. **超时保护**：每种块类型设定默认超时上限
4. **来源白名单**：`allowedOrigins` 字段预留（当前版本未强制）
